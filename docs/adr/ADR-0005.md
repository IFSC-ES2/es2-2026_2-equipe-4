# ADR-0005: Login com JWT e consulta pública de projetos

## Status

**Aceita.** Implementada na Sprint 2. Complementa a
[ADR-0004](ADR-0004.md).

## Contexto

Qualquer visitante deve poder consultar os projetos. Para publicar, é
necessário fazer login, pois cada projeto precisa ter um usuário responsável.

## Decisão

Usar Spring Security com JWT, um token que comprova o login do usuário.

- Cadastro, login e consulta de projetos são públicos.
- Após o login, a API entrega um token ao front-end.
- Para enviar arquivos e dados de projetos, o front-end envia esse token no
  cabeçalho `Authorization: Bearer <token>`.
- A API valida o token e associa o projeto ao usuário autenticado.
- O servidor valida cada requisição protegida sem manter uma sessão de login.

## Alternativas

- **Publicação sem login:** não garante a identificação do usuário responsável.
- **Sessão no servidor:** é uma opção possível, mas exige que o servidor
  mantenha os dados da sessão.
- **JWT (escolhido):** permite validar o login pelo token, mas exige cuidar
  de sua proteção e expiração.

Estas alternativas descrevem as opções aplicáveis.

## Consequências

- Visitantes consultam projetos sem criar uma conta.
- A publicação depende de um token válido.
- O front-end guarda o token em `localStorage`, o que exige cuidado para
  impedir seu acesso por scripts maliciosos.
- O segredo JWT e as credenciais fixas ainda precisam ser corrigidos,
  conforme a [issue #100](https://github.com/IFSC-ES2/es2-2026_2-equipe-4/issues/100)
  e o [registro de riscos](../riscos.md).
