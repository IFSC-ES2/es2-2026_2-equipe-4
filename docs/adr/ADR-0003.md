# ADR-0003: Front-end em React

## Status

**Aceita.** Substitui somente a escolha de HTML, CSS e JavaScript sem framework
para o front-end da [ADR-0002](ADR-0002.md). As decisões de back-end, banco e
containers daquela ADR continuam vigentes.

## Contexto

A ADR-0002 planejava páginas estáticas. Antes de implementar a interface do
MVP, a equipe decidiu usar componentes para manter formulários, navegação e
estado das páginas em uma aplicação React. A decisão foi tomada na Sprint 1;
não houve migração de uma interface estática já entregue.

## Decisão

Usar React no front-end, com Vite para desenvolvimento e build. O código fica
em `src/frontend/`; a aplicação usa `react-router-dom` para navegação.
O React consome a API Spring Boot por HTTP e não acessa o MongoDB diretamente.

## Alternativas consideradas

| Alternativa | Avaliação |
|---|---|
| Manter HTML, CSS e JavaScript sem framework | Menos dependências e configuração, mas maior trabalho manual para compartilhar componentes e estado entre páginas. Era o plano inicial da ADR-0002. |
| Adotar React | Exige build, dependências e aprendizado de JSX; facilita compor as páginas e reaproveitar componentes. Foi a opção escolhida. |

Não há registro de avaliação comparativa de outros frameworks; este ADR não
atribui à equipe uma análise que não foi documentada.

## Consequências

- Componentes e estado podem ser compartilhados entre páginas, com testes de
  interface em Vitest.
- O desenvolvimento requer Node.js, instalação de dependências e build do Vite.
- O contrato HTTP com a API continua sendo uma fronteira separada; mudanças
  de campos ou rotas exigem integração e testes nas duas partes.

## Relação com o MVP

React sustenta as páginas de cadastro, login e submissão e a evolução da
listagem pública. A escolha da interface não altera a arquitetura em camadas
da [ADR-0001](ADR-0001.md).
