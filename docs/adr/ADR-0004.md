# ADR-0004: Vitrine de projetos universitários

## Status

**Aceita.** Decisão da revisão da Sprint 1 em 23/09/2026, implementada na
Sprint 2. Altera o domínio do MVP, sem substituir a arquitetura em camadas da
[ADR-0001](ADR-0001.md).

## Contexto

O plano inicial descrevia submissão de artigos acadêmicos e PDFs. A equipe
decidiu que o produto seria uma vitrine de projetos universitários, com
cadastro, publicação por usuário e consulta pública. O modelo de artigos
deixou de representar os dados centrais do produto.

## Decisão

Reaproveitar o fluxo e a persistência existentes, remodelando-os para
`Projeto`, com título, resumo, tema, autores, tecnologias, imagens opcionais
e links de repositório e demonstração. A coleção MongoDB é `projetos`; a API
usa `/projetos`. O arquivo enviado é guardado no GridFS. O identificador do
autor é atribuído no servidor a partir do usuário autenticado, conforme a
[ADR-0005](ADR-0005.md).

## Alternativas consideradas

| Alternativa | Consequência |
|---|---|
| Manter artigos e PDFs como domínio principal | Preservaria o plano inicial, mas não atenderia à decisão de produto da revisão da sprint. |
| Criar um fluxo de projetos paralelo ao de artigos | Duplicaria modelo, rotas e persistência para um MVP pequeno. |
| Remodelar o fluxo existente para projetos | Reaproveita a base implementada, mas exige rever documentação, testes e issues legadas. Escolhida. |

Esta tabela explicita alternativas aplicáveis na revisão; não há registro de
votação formal entre elas.

## Consequências

- As issues e os documentos antigos sobre artigos devem ser lidos como
  histórico, ou revisados antes de orientar trabalho novo.
- O MongoDB e o GridFS permanecem; a apresentação de imagens depende de uma
  rota de leitura e não é presumida como concluída.
- Front-end, API e testes precisam compartilhar o contrato de projetos para
  evitar retrabalho.
