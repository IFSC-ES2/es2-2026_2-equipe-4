# ADR-0001: Stack Tecnológica do Projeto

## Status

**loading**

## Contexto

A definição da stack tecnológica deve considerar principalmente as necessidades do MVP, a experiência prática dos integrantes da equipe, a facilidade de desenvolvimento e a possibilidade de evolução futura.

A prioridade será utilizar tecnologias conhecidas pela equipe sempre que possível, evitando a introdução de complexidade desnecessária.

A stack será organizada de acordo com as três principais camadas do sistema:

**Front-end → API → Banco de dados**

Além disso, os serviços serão executados utilizando **Docker**, permitindo maior reprodutibilidade do ambiente de desenvolvimento e execução.

## Decisão

A stack tecnológica será composta inicialmente por **HTML, CSS e JavaScript no front-end**, **Java com Spring Boot no back-end** e **MongoDB como banco de dados principal**.

O **MySQL** será mantido como uma alternativa de contingência caso sejam identificadas limitações relevantes na utilização do MongoDB.

### Front-end - web

Para o desenvolvimento do front-end, serão utilizados:

* **HTML**
* **CSS**
* **JavaScript**

A escolha dessas tecnologias tem como objetivo facilitar o desenvolvimento e a integração com a API, garantindo uma interface funcional para interação com o sistema.

Neste momento, o objetivo principal não é escalar a aplicação ou aumentar sua complexidade, mas sim disponibilizar as funcionalidades necessárias para o MVP.

A organização inicial do projeto será:

```text
frontend/
│
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── api.js
│   └── app.js
└── Dockerfile
```

> Pode haver uma ou mais páginas na primeira entrega. A estrutura apresentada representa apenas uma demonstração inicial da organização do projeto.

### Back-end

Para o desenvolvimento da API, será utilizada uma arquitetura **RESTful**, utilizando **Spring Boot com Java**.

A API será responsável pela comunicação entre o front-end e o banco de dados.

Para a persistência e comunicação com o banco, será utilizado **Spring Data MongoDB** para a conexão com MongoDB.

A escolha dessa stack se deve à familiaridade dos integrantes do grupo com a linguagem Java e com o ecossistema Spring. Além disso, a plataforma oferece diversas bibliotecas e ferramentas que facilitam e aceleram o desenvolvimento.

Embora a configuração inicial possa apresentar maior complexidade e verbosidade, após a configuração inicial a estrutura facilita a manutenção e a evolução da aplicação.

A estrutura inicial será:

```text
backend/
└── src/main/java/
    └── com.projeto/
        ├── controller/
        ├── service/
        ├── repository/
        ├── entity/
        └── dto/
```

### Banco de dados

O banco de dados principal escolhido será o **MongoDB**.

O **MySQL** será mantido como uma alternativa de contingência, e não como banco utilizado simultaneamente pela aplicação.

Caso sejam identificados problemas ou limitações na utilização do MongoDB, o MySQL poderá ser considerado como uma segunda opção.

A escolha do MongoDB está relacionada à sua capacidade de trabalhar com dados no formato de documentos, característica que pode ser útil para as necessidades do projeto.

Entretanto, a equipe possui pouca experiência prática com MongoDB. Por isso, será necessário realizar estudos e consultar a documentação da ferramenta durante o desenvolvimento.

O banco de dados será executado em um container, reduzindo a necessidade de configurações específicas no ambiente de desenvolvimento.

### Containers e ambiente

Os serviços serão executados utilizando **Docker**.

A utilização de containers tem como objetivo:

* padronizar o ambiente de desenvolvimento;
* reduzir diferenças de configuração entre máquinas;
* facilitar a execução do projeto;
* facilitar a reprodução do ambiente;
* simplificar o deploy em diferentes ambientes.

A estrutura inicial poderá utilizar uma configuração semelhante a:

```text
projeto/
│
├── frontend/
│   └── Dockerfile
│
├── backend/
│   └── Dockerfile
│
├── docker-compose.yml
└── README.md
```

## Consequências

Inicialmente, algumas das tecnologias escolhidas podem apresentar maior complexidade e verbosidade durante a configuração. Entretanto, após a configuração inicial, a estrutura adotada facilita o crescimento e a evolução da aplicação.

A escolha de HTML, CSS e JavaScript reduz a complexidade do front-end para o MVP.

A utilização de Spring Boot e Java fornece uma estrutura organizada para o desenvolvimento da API, embora exija uma configuração inicial maior.

A adoção do MongoDB permite trabalhar com documentos e oferece flexibilidade na estrutura dos dados, mas exige que a equipe desenvolva maior conhecimento sobre a tecnologia.

A utilização de containers facilita a reprodução do ambiente de desenvolvimento e execução.

### Consequências positivas

* A stack utiliza tecnologias conhecidas ou alinhadas à experiência dos integrantes.
* O front-end possui baixa complexidade inicial.
* O Spring Boot fornece uma estrutura organizada para o desenvolvimento da API.
* O MongoDB oferece flexibilidade para armazenamento baseado em documentos.
* O Docker facilita a reprodução do ambiente.
* A stack pode evoluir futuramente sem exigir necessariamente uma substituição completa das tecnologias.
* O MySQL permanece disponível como alternativa caso o MongoDB não atenda às necessidades do projeto.

### Consequências negativas ou riscos

* Existe um risco de aumento da complexidade durante a configuração inicial do Spring Boot e Docker.
* A equipe possui pouca experiência com MongoDB, podendo ser necessário um período adicional de aprendizado.
* A utilização de múltiplas tecnologias exige que os integrantes compreendam como as diferentes camadas se comunicam.
* Algumas decisões tomadas para simplificar o MVP podem precisar ser revistas caso o sistema cresça significativamente.

## Ações necessárias

* Estudar a documentação oficial do MongoDB.
* Estudar e configurar o Spring Data MongoDB.
* Realizar testes de integração entre a API e o banco de dados.
* Criar os Dockerfiles dos serviços.
* Criar a configuração do Docker Compose.
* Validar a execução de todos os serviços utilizando containers.
* Validar a comunicação entre front-end, API e banco de dados.
* Avaliar a necessidade de utilização do MySQL como alternativa.

## Relação com o MVP

O MVP tem como objetivo entregar um sistema funcional que atenda às características e funcionalidades definidas para a primeira entrega.

As decisões relacionadas à stack tecnológica foram tomadas buscando equilibrar **simplicidade, familiaridade, velocidade de desenvolvimento e possibilidade de evolução**.

A prioridade nesta etapa é garantir o funcionamento das funcionalidades principais, evitando a introdução de tecnologias que adicionem complexidade sem contribuir diretamente para os objetivos do MVP.

A stack escolhida fornece uma base suficiente para implementar, testar e executar o sistema, mantendo aberta a possibilidade de evolução futura.
